# 轻量化人脸考勤系统

这是我用 Python、OpenCV 和 SQLite 写的一个 Windows 离线考勤客户端。

这个项目最初只是一个很小的练习：摄像头检测到人脸后，手工输入姓名并写入文本文件。继续往下做时，我发现“能演示”和“能使用”完全是两回事，所以逐步补上了身份识别、员工建档、管理员认证、数据库、备份、异常处理和升级迁移。当前版本是 **1.2.0**。

我把整个迭代过程写成了一篇博客：[从人脸检测 Demo 到可以落地的考勤客户端](docs/blog.md)。

## 现在能做什么

- 在本机采集员工人脸，每人默认保存 20 张灰度样本
- 使用 Haar 检测人脸，使用 LBPH 在本地完成身份识别
- 区分上班和下班打卡，并阻止短时间内重复提交
- 对过暗、过曝和模糊画面进行拦截
- 新增员工时检查疑似重复人脸
- 支持员工停用、删除和重新采集人脸
- 使用 PBKDF2-SHA256 保存管理员密码
- 将数据写入 SQLite，支持 CSV 导出和数据库备份
- 自动备份 1.0 数据，再升级到 1.2 所需的数据结构
- 日志自动轮转，摄像头断开后可以手动重连

## 运行环境

- Windows 10 或 Windows 11
- 64 位 Python 3.11 或 3.12
- 一个可用的摄像头

安装：

```powershell
Set-ExecutionPolicy -Scope Process Bypass
.\install.ps1
```

启动：

```powershell
.\start.ps1
```

首次启动时会要求设置管理员密码。进入管理员控制台后，选择“新增员工”，填写员工编号和姓名，再正对摄像头完成采集。

## 数据放在哪里

程序不会把人脸上传到网络。数据库、备份、配置和日志默认保存在：

```text
%LOCALAPPDATA%\FaceAttendance\
├─ attendance.db
├─ config.json
├─ backups\
└─ logs\application.log
```

测试或便携运行时，可以通过环境变量修改位置：

```powershell
$env:FACE_ATTENDANCE_HOME = "D:\FaceAttendanceData"
.\start.ps1
```

## 识别流程

```text
摄像头
  → Haar 定位人脸
  → 亮度和清晰度检查
  → 裁剪为 160 × 160 灰度图
  → LBPH 预测员工标签和识别距离
  → 连续多次识别稳定
  → 允许上班或下班打卡
```

LBPH 返回的是距离，不是百分比。距离越低，当前人脸与建档样本越接近。默认阈值是 65，但这个值不能直接照搬到所有环境。我建议在实际摄像头、实际照明和真实员工样本上重新测试，再决定是否收紧。

## 配置

程序第一次运行后会生成 `config.json`。可配置项包括：

- 摄像头编号
- 识别阈值和连续稳定次数
- 防重复打卡时间
- 建档样本数
- 人脸亮度、过曝和清晰度门槛
- 重复人脸判断阈值
- 设备名称和备份保留天数

修改配置后需要重启程序。仓库里的 [config.example.json](config.example.json) 包含全部默认值。

## 测试

```powershell
.\.venv\Scripts\python.exe -m unittest discover -s tests -v
```

测试覆盖密码散列、员工和人脸样本事务、防重复打卡、上班/下班记录、CSV 导出、备份、数据库迁移、图像质量门槛、LBPH 训练和重复人脸判断。测试使用代码生成的灰度纹理，不依赖外部人像素材。

## 我刻意保留的边界

这个版本没有专业活体检测。亮度检查、清晰度检查和连续识别只能改善使用体验，不能防住手机视频或高质量照片。因此，我只把它定位为低风险、有人值守或可以人工复核的内部工具。

如果考勤结果会直接影响工资，或者设备需要无人值守，我不会建议原样部署。更合适的做法是增加经过验证的活体方案、权限审计、排班规则和集中式数据管理。
